### 🎯 My rules

- 🧠 **Attempt first:** spend 30–45 minutes understanding and attempting the problem before looking for a full solution.
- 📝 **Pseudocode first:** write the logic before randomly typing code.
- 🧪 **Test properly:** normal case + boundary case + unusual/invalid case.
- 🔧 **Refactor:** once it works, clean names, remove repetition and improve structure.
- 💾 **Commit daily:** every meaningful practice session gets pushed to GitHub.
- 🗣️ **Explain my code:** if I can't explain a loop, condition or function, I don't consider the problem truly completed.

## 📈 How Progress Works

The repository includes a GitHub Action that checks for `q1.py` → `q18.py` on every push.

When a question file exists, the dashboard marks it as **completed**. When a new question is committed, the README automatically updates.

**Important:** a file existing means *the implementation has been committed*, not that the solution is necessarily perfect. I still need to test and understand it.
